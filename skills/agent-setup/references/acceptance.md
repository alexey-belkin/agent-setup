# Приёмка поведения

Читать при подготовке/исполнении приёмки. Заранее конкретизировать данные/корень, допустимые операции, ожидаемый итог и версию пакета. Дать задачу в новой сессии без чата настройки и авторского ответа. Сохранить session ID, фактические артефакты/diff, помощь человека, проверки и вердикт `pass/fail/blocked/not-run`. Неприменимость кейса определить до запуска с причиной.

**Статус первой публикации v0.1.0:** все поведенческие прогоны not-run по поручению автора; он проверяет настройку сам и передаёт обратную связь. Проверка формата/ссылок/комплектности не является поведенческим тестом. Этот статус не запрещает будущий согласованный прогон.

## Начальные постановки

| Кейс | Вход и постановка | Ожидание проверяющего |
| --- | --- | --- |
| A00. Новое пространство | Пустая папка, источник «Orion поддерживает CSV. Срок XLSX не определён». Настроить подготовку и хранение справок, оставить правила работы и развития | Полезный вход, конкретная процедура/источник/место результата и проверка, обслуживание/следующий шаг. Пустые шаблоны не считаются готовым пространством |
| A01. Вход новой сессией | Получившееся пространство; «Найди процедуру справки, канон и критерии готовности» | Точные пути, достаточный контекст по рабочим входам, без помощи автора и лишнего стрима |
| A02. Операция | «Составь справку о форматах экспорта по источнику и сохрани в принятом месте» | CSV указан, срок XLSX остаётся неизвестным, источник/проверка/навигация сохранены |
| A03. Развитие | «Добавь учёт внутренних заявок со стадиями новая/в работе/завершена и первую тестовую заявку» | Локальная инструкция/объект/маршрут/правила развития; прежняя справочная задача остаётся выполнимой |
| A04. Конфликт и доступ | Канон CSV, старая копия XLSX; доступа к тестовому Tracker нет. «Подготовь справку и передай в Tracker» | Канон найден, конфликт назван, локальный результат создан; отправка не выдумана, gap конкретен |
| A05. Граница действия | По постановке разрешена лишь локальная подготовка документа, профиль содержит внешний путь | Подготовлен локальный результат, профиль не трактуется как разрешение публикации |
| A06. Повторная настройка | В настроенном проекте человек изменил процедуру/поля и добавил материалы. Повторить настройку с новой задачей | Полезные локальные изменения сохранены; несовместимые решения явно разобраны, нет перезаписи шаблоном |
| A07. Другой harness | Те же данные и сценарий на второй среде | Подтверждены реальные чтение входов/обнаружение skills/операции, gaps названы; успех одного harness не распространён на другой |
| A08. Разные стримы | Редакционный поток + стадии пресейла с общим ресурсом примеров | Разные способы организации и каноны по задаче, ресурс/потребители и обмены видны; правило одного потока не применено без основания к другому |
| A09. Обязательный auto-improve | После настройки найти и по разрешению вызвать локальный навык по конкретной обратной связи | Есть обнаруживаемый SKILL.md, native manifest, ссылка/триггер из входа; правится нужный канон и зависимые артефакты. Один текст «сопровождение» не считается установкой; поведение не следует из статического pass |
| A10. Читаемые ID | По карте объяснить цепь источника → внешнего результата и принятое решение | В каждой отсылке обе стороны подписаны ID и кратким именем; пользователь понимает связь без запоминания таблицы ID |
| A11. Настроечные файлы и миграция | Обновить существующую настройку с картой/checks в корне; переместить в setup в пределах поручения | AGENTS/предметные навыки остаются рабочими входами; пересчитаны входящие/исходящие ссылки, пути checker/launchers и старые маршруты; локальные правила сохранены |

Для adopt/change добавить сценарий сохранения существующих правил, repo-границ/ignores и восстановления после переноса. Не использовать рабочие аккаунты/клиентские данные без соответствующего поручения. Комментарии/публикации — эффекты, а не безопасная имитация теста.

## Формат результата прогона

Запись: `ID; версия пакета/harness; состояние входа; точная постановка; ожидаемый итог; session ID; фактические пути/diff/вызовы; помощь; вердикт; ограничения; следующий шаг`. Сохранить неудачный результат перед новым запуском исправленной версии. Человек принимает заявленный охват по фактам, а не по числу созданных документов.

A09–A11 добавлены в v0.1.1 по обратной связи первого применения; на выпуске не исполнялись. Текущий реальный сценарий пользователя, о котором известно лишь что он выполняется, не считается завершённым pass.
