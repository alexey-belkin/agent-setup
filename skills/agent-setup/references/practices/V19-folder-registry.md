# V19. Registry папки

**ID:** V19. **Версия:** 0.2. **Редакция:** 11.11.2026.
**Форма реализации:** реестр; при необходимости генератор. **Описание:** на ревью. **Поведенческая проверка:** not-run.

## 1. Когда выбирать

По именам файлов нельзя быстро выбрать нужный артефакт или оценить состав папки. Реестр даёт ссылку и содержательное назначение, иногда ID/тип/происхождение. Применяется локально, не требует переустройства всего проекта. Если небольшая действующая таблица уже решает задачу, второй registry не нужен.

## 2. Как работает

Для оговорённого уровня/семейства ведётся список артефактов. У строки минимум путь и назначение; дополнительные поля вводятся под реальные решения читателя. Добавление/переименование/удаление артефакта обновляет запись и ссылки в той же операции. Корневой или локальный вход указывает, когда открывать реестр.

Назначить владельца каждого поля. Ручной реестр сам хранит описание. В производном реестре путь и описание собираются из метаданных артефакта: исправляется источник, не выходная таблица. Если часть полей ручная, генератор должен сохранять их по устойчивому ключу и явно обрабатывать переносы. Хеш/mtime — технические признаки, они не доказывают дату создания, актуальность сведений или одобрение. Каталог «что выбрать для задачи» отличается от файлового перечня; один не подменяет другой.

## 3. Варианты и сочетания

| Вариант | Когда выбирать | Цена / ограничения |
| --- | --- | --- |
| Раздел Registry в README | Назначение папки и список нужны вместе | Не превращать README в длинную обязательную выгрузку |
| Отдельный REGISTRY.md по ссылке | Большой список нужен лишь для поиска/ревью | Дополнительный переход оправдан отдельным сценарием |
| Генерируемая таблица | Много файлов/метаданных, ручной список расходится | Нужны генератор, источники полей, проверка drift; это отдельный механизм V08 |

Для генерирования обязателен контракт источников полей и стабильного повторного запуска. [V16](V16-policy-linter.md) может проверять drift; сам registry не требует linter, БД или skill. Реестр ресурсов может включать существующий артефакт вне папки ссылкой — без обязательного переноса/дублирования.

## 4. Минимальный пример

Иллюстрация: библиотека нейтральных методических заметок в `notes/`. В README указан scope «файлы этого уровня» и таблица:

```markdown
## Registry
| Артефакт | Когда нужен |
| --- | --- |
| [N-01. Проверка источника](N-01-source-review.md) | При включении внешнего утверждения в публикацию |
| [N-02. Передача редактору](N-02-handoff.md) | При завершении черновика |
```

Оба файла существуют; смысл заметок записан внутри. Добавляется `N-03-style.md` — одновременно появляется строка с его назначением. Если выбран генератор, содержательное описание хранится, например, в `description` frontmatter каждого файла, а таблица помечена как производная. Такой переход — решение настройки, не требование переписать все существующие документы.

## 5. Внедрение и развитие

Определить охват: один уровень/рекурсия/экземпляры/внешние ссылки; технические и архивные исключения. Выбрать место и только необходимые поля. При автоматизации описать, какие поля разрешено править вручную, предусмотреть режим проверки без записи, детерминированный порядок и ошибку при неполных обязательных метаданных. Для автоматизации поставляются [build_registries.py, конфигурация и инструкция](../workspace-tools.md#3-реестр-из-метаданных); поддержаны отдельный файл и блок README. Маленький ручной вариант применим без генератора.

Отдельный skill имеет смысл для повторяемого добавления артефакта, не для открытия таблицы. При миграции сохранить ручные сведения и устойчивые ссылки. Восстановление возвращает таблицу и изменённые источники вместе; перегенерация не восстанавливает утраченные ручные поля сама по себе.

## 6. Приёмка и границы

**Статус исполнения кейсов:** not-run.

| Кейс | Исходное состояние и действие | Ожидаемый наблюдаемый итог |
| --- | --- | --- |
| V19-T1 | В notes добавлен третий файл | Из входа достижима строка с правильной ссылкой и различимым назначением |
| V19-T2 | Файл переименован; ручная дата происхождения задана | Старой ссылки нет, новая разрешается, дата сохранена как факт источника |
| V19-T3 | У производной строки вручную исправлено описание | Check обнаруживает drift; исправление переносится в метаданные; повторная генерация без изменений стабильна |

Доступность записи не доказывает качество её содержания. Избыточные размеры/хеши могут мешать выбору и требуют обслуживания. **P2:** навигация по общему контексту; **P6:** реестр обновляется вместе с артефактами. Не является полной описью процессов или заменой карты зависимостей.
