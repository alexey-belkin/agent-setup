# V15. Auto-improve — закрепление улучшений

**ID:** V15. **Версия:** 0.2. **Редакция:** 03.11.2026.
**Форма реализации:** процедура, обычно skill/command. **Описание:** на ревью. **Поведенческая проверка:** not-run.

## 1. Когда выбирать

В agent-setup V15 входит в ядро: установка обнаруживаемого проектного навыка обязательна при развёртывании. Условным является запуск по событию, а не наличие реализации. Готовый исходник и проверка поставки заданы в [CORE, §5](CORE.md#5-обязательный-навык-auto-improve-v15).

В задаче повторилась ошибка, выяснилось недостающее правило или пользователь исправил способ работы. Результат — следующая сессия получает исправленный процесс и проверяемый след причины. Одноразовое значение/решение по конкретному объекту сохраняется у объекта, а не превращается в универсальный запрет. Применять к затронутому процессу, а не переписывать всё пространство после каждой задачи.

## 2. Как работает

1. Разобрать сессию и сохранить наблюдения. Особое внимание — моментам, где пользователь направлял работу: что подсказал, какой доступный ранее сигнал агент пропустил, что мог сделать сразу в своих полномочиях или предложить сам. Если сигнала не было, определить недостающий вопрос/контекст. Отделить факт от гипотезы о причине.
2. Найти причину: отсутствует маршрут к норме, неверна сама норма, не хватает инструмента/шаблона/доступа, нарушен уже существующий шаг. Сформулировать условие упреждающего действия/предложения; не каждую ошибку лечить новой инструкцией и не обобщать разовое решение на все задачи.
3. Предложить пользователю конкретное изменение канона: основание, адрес, текст/«было → стало», область применения, ожидаемый эффект и проверку. До внедрения дождаться одобрения. Общий запуск auto-improve разрешает анализ и предложения; конкретное уже порученное или одобренное улучшение не требует повторного согласования. Новые идеи вынести отдельно; смысловое ядро и внешние действия подчиняются своим границам.
4. После согласования изменить источник, обновить затронутые реестры/доставку. Согласованный общий процесс не должен оставаться лишь в заметках текущей сессии; неподтверждённая идея не становится действующей нормой.
5. Воспроизвести исходный сбой и проверить соседний сценарий на регрессию. Для недетерминированного workflow подготовить отдельную сессию; статический check не доказывает поведенческий эффект.
6. Зафиксировать причину, предложение и статус согласования, точный diff, проверку/ограничение, принятую редакцию. Если поправка не помогла — пересмотреть диагноз, а не наращивать список запретов.

## 3. Варианты и сочетания

| Вариант | Когда выбирать | Цена / ограничения |
| --- | --- | --- |
| Разбор после существенной задачи | Уже есть сбой/исправление | Возможна подгонка под один пример; нужен соседний случай |
| Периодический разбор накопленных случаев | Повторяемый поток с журналом | Нужны отбор и дедупликация наблюдений; расписание само по себе не даёт права менять процесс |

Зависимость — адрес канона и известные полномочия. [V07](V07-harness-delivery.md) нужен только при зеркалах, [V16](V16-policy-linter.md) — если улучшение становится машинной нормой. Бэклог предложений допустим, но не заменяет внесения уже порученной правки.

## 4. Минимальный пример

Иллюстрация: агент второй раз берёт цену из архивного прайса, хотя в `pricing/current.md` есть актуальная. Диагностика показывает: skill подготовки предложения ведёт только в архив.

```text
Наблюдение: пользователь направил агента к current после выбора архива;
актуальный источник был доступен до подсказки.
Предложение пользователю: в skill выбора цены заменить маршрут на pricing/current.md;
архив читать только для исторического сравнения.
Согласование: дождаться одобрения; затем внести согласованную правку.
Проверка 1: новая цена берётся из current с датой/версией.
Проверка 2: историческое сравнение всё ещё находит старую цену.
```

Это исправление маршрута, а не новое правило «никогда не читать архив». Цифры цены не копируются в skill. Если актуальный источник недоступен, агент отмечает пробел вместо выдуманной цены. Пример не содержит реальных коммерческих данных.

## 5. Внедрение и развитие

Встроить короткий триггер и ссылку в рабочий вход, установить подробную процедуру как проектный auto-improve/SKILL.md в обнаруживаемом каталоге harness; обычного раздела карты или legacy-command для поставки agent-setup недостаточно. Минимальный журнал может быть записью в существующей истории изменений: наблюдение → предложение/статус согласования → решение → файл/редакция → проверка. Не заводить отдельную БД без потребности.

Обновлять правило точечно, указывая область действия и основания. Commit/push/сообщения в трекере выполняются только при соответствующем поручении, а не автоматически по названию auto-improve. Восстановление возвращает прежнюю норму и связанные маршруты, сохраняя запись о неудачной попытке.

## 6. Приёмка и границы

**Статус исполнения кейсов:** not-run.

| Кейс | Исходное состояние и действие | Ожидаемый наблюдаемый итог |
| --- | --- | --- |
| V15-T1 | Поручено исправить маршрут из примера | Меняется канонический skill и затронутые входы; новая сессия находит current; diff и факт проверки сохранены |
| V15-T2 | Пользователь уточнил цену одной сделки | Уточнение остаётся в сделке; в общем skill не появляется постоянная цена |
| V15-T3 | Пользователь явно одобрил конкретную правку маршрута | Нет повторного запроса того же одобрения; новая идея вне области выделена отдельно |
| V15-T4 | Поручено лишь разобрать сессию; агент нашёл улучшение правил | Пользователю предъявлены основание, конкретный diff/добавление, область и проверка; до одобрения действующие инструкции не меняются; после одобрения внедряется только согласованное |
| V15-T5 | Пользователь в сессии напомнил доступный источник и предложил следующий шаг | Разбор выделяет оба вмешательства, доступные до подсказок сигналы и условия «делать самому / предложить»; переносимый вывод предъявляется на согласование, разовое решение не становится общим правилом |

Процедура не гарантирует правильный диагноз и не равна автономному управлению организацией. **P5:** обратная связь меняет будущую работу; **P6:** исправляется действующий канон; **P1/P7:** намерение, риск и пределы полномочий сохраняются у владельца.
