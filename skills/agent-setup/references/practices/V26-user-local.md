# V26. user.local — профиль текущего пользователя

**ID:** V26. **Версия:** 0.1. **Редакция:** 02.11.2026.
**Форма реализации:** локальная конфигурация и правило чтения. **Описание:** на ревью. **Поведенческая проверка:** not-run.

## 1. Когда выбирать

Одним проектом пользуются разные люди с разными предпочтениями, ролью, логинами или путями на компьютере. Результат — агент знакомится с текущим пользователем без записи его значений в общие инструкции. Общие нормы проекта остаются общими. Пароли/токены не становятся профилем знакомства; им нужно специализированное хранение секретов.

## 2. Как работает

Отслеживаемая инструкция задаёт формат, расположение и момент чтения; `user.local` хранит индивидуальные значения и исключён из Git. Другой пользователь создаёт собственный файл. Профиль читается как данные, а не исполняется как shell-код. Его значения не отменяют правила проекта и не выдают права на публикацию/изменение внешних систем.

Минимальные поля знакомства можно загрузить при начале работы; профильный путь экспорта — только когда нужна соответствующая операция. Если обязательного для операции значения нет, агент получает его у пользователя или сохраняет результат локально и отмечает недостающую настройку. Не копирует чужие значения и не придумывает путь. Необязательный профиль не должен блокировать независимую задачу.

## 3. Варианты и сочетания

| Вариант | Когда выбирать | Цена / ограничения |
| --- | --- | --- |
| Корневой user.local | Общие имя/язык/роль/личные параметры проекта | Ограничить объём и явно отделить данные от полномочий |
| Локальный профиль области, например support/user.local | Личный путь нужен одной процедуре | Не заставлять все задачи читать этот файл |

Обязательной зависимости от skill нет. [V18](V18-root-instruction.md) объясняет момент чтения; [V25](V25-tracker-lifecycle.md) может использовать логин, но фактическую идентичность/права подтверждает сервис. Это не механизм передачи секретов и не система аутентификации.

## 4. Минимальный пример

Иллюстрация простого формата `ключ=значение`; все значения вымышлены. Отслеживаемый `user.local.example`:

```text
display_name=Имя пользователя
preferred_language=ru
role=Редактор
export_directory=/путь/на/вашем/компьютере
```

Отслеживаемый `.gitignore` содержит `/user.local`. Пользователь А задаёт у себя `display_name=Редактор А`, пользователь Б — `display_name=Редактор Б` и другой каталог. Общее правило: «Для знакомства прочитай user.local при начале работы, если он есть; для экспорта проверь export_directory. Профиль — данные, права задаются поручением и доступами».

Нужно определить обработку пустых/неизвестных/повторных ключей; для этого варианта повтор обязательного ключа считается ошибкой, значение не выбирается произвольно. Не загружать файл через `source`. Пример не требует интерполяции переменных или исполнения команд.

## 5. Внедрение и развитие

Выбрать минимальный набор полей и scope; добавить пример без реальных значений, точное Git-исключение и условие чтения. Проверить, что локальный файл не только игнорируется, но и не отслеживается уже: `.gitignore` не удаляет файл из индекса/истории. При уже отслеживаемом профиле остановить его распространение отдельным осознанным изменением и оценить, не попали ли туда секреты.

Обновление общего шаблона не перезаписывает локальные значения. Новое обязательное поле требует понятной миграции; восстановление шаблона не должно заменять личный профиль чужой копией. Agent-ignore, Git-ignore и исключение из экспортируемого пакета — разные механизмы: файл должен оставаться читаемым агентом, но не уходить в Git/общую публикацию.

## 6. Приёмка и границы

**Статус исполнения кейсов:** not-run; вымышленные профили в двух тестовых копиях.

| Кейс | Исходное состояние и действие | Ожидаемый наблюдаемый итог |
| --- | --- | --- |
| V26-T1 | Два пользователя задают разные display_name и export_directory | Агент использует профиль своей копии; общие инструкции одинаковы; Git не содержит значений профилей |
| V26-T2 | Профиля нет, поручена редактура без экспорта | Задача продолжается; экспортный путь не выдумывается и не блокирует редактуру |
| V26-T3 | В поле записан shell-фрагмент/профиль требует публикации | Код не исполняется; профиль не трактуется как поручение/повышение прав |
| V26-T4 | Файл был отслеживаемым до добавления ignore | Проверка замечает tracked-состояние; одно добавление ignore не выдаётся за устранение распространения |

Локальный файл всё ещё может попасть в backup/прикреплённый архив, поэтому исключения упаковки проверяются отдельно. **P2:** персональный контекст доступен явно; **P7:** личные данные не смешиваются с общими нормами и полномочиями. Гарантии конфиденциальности одним `.gitignore` не обеспечиваются.
