# V18. AGENTS.md — корневая инструкция

**ID:** V18. **Версия:** 0.1. **Редакция:** 02.11.2026.
**Форма реализации:** инструкция и навигация. **Описание:** на ревью. **Поведенческая проверка:** not-run.

## 1. Когда выбирать

Пространство живёт дольше одной сессии; следующему агенту нужны назначение, общие границы и маршрут к своей задаче. Результат — агент начинает работу без пересказа чата владельцем. Для разового ответа без сохраняемого пространства достаточно самой постановки.

Нужны понятные области работы и источник действующих правил. Если они неизвестны, сначала выяснить их; заголовки AGENTS этого не заменяют. Практика относится к общему входу проекта; детали отдельных стримов могут различаться.

## 2. Как работает

1. В корне хранится один общий контракт: назначение, как выбрать область, постоянно нужные короткие нормы, полномочия, критерий завершения и изменение структуры.
2. Для каждого маршрута указаны ссылка и условие чтения. Профильные правила находятся рядом с потоком/skill, данные — у своего источника. По ссылкам можно дойти до релевантного рабочего контекста; исключения архивов/технических ветвей явно очерчены.
3. Агент определяет область задачи и добирает достаточный контекст по этому маршруту. Он не читает инструкции другого стрима только потому, что они существуют.
4. При добавлении типа задач обновляются локальные нормы и путь из входа. При конфликте норм агент устанавливает применимую редакцию/область, а не выбирает удобную молча.

Короткость — средство ограничения порции, не самоцель. Если правило нужно в каждой задаче и занимает несколько строк, его вынос создаёт лишний вызов. Рабочий ориентир — до 15 000 токенов в одной собираемой порции, с фактическим измерением. Два коротких файла, всегда читаемых подряд, могут оказаться хуже одного. Контекст человека и агента общий; отдельный README оправдывается функцией, а не аудиторией.

## 3. Варианты и сочетания

| Вариант | Когда выбирать | Цена / ограничения |
| --- | --- | --- |
| Один вход с короткими нормами и прямыми маршрутами | Небольшое пространство | Следить за ростом обязательного чтения |
| Общий вход + локальные инструкции потоков | Разные процессы, общие границы | Поддерживать область действия и связи; не дублировать нормы |

Обязателен способ доставки входа выбранному harness: автоматически обнаруживаемый файл либо явное чтение по запуску. Само имя файла не доказывает загрузку. [V07](V07-harness-delivery.md) добавляет доставку в несколько harness; [V19](V19-folder-registry.md) — навигацию больших папок. V03 (маршруты/объём), V23 (достижимость) и V20 (локальность норм) заданы [ядром проектирования](CORE.md), а не выбираются как отдельные опции; эта карточка описывает реализацию общего входа.

В существующем пространстве общий контракт может уже жить в читаемом README. Сначала проверить его функцию и доставку, затем выбрать сохранение канона/проверяемый адаптер либо согласованный перенос. Второй самостоятельный набор общих норм ради имени AGENTS создавать не нужно.

## 4. Минимальный пример

Иллюстрация для вымышленного издательского проекта. Содержимое корневого `AGENTS.md`:

```markdown
# Рабочее пространство издательства
Перед работой выбери область по задаче.
- Редактура: читать editorial/AGENTS.md — при создании и правке материалов.
- Учёт изданий: читать catalog/AGENTS.md — при изменении карточек и выпусков.
Общие нормы: указывать источник фактов; не придумывать согласование.
Публикация выполняется только в пределах поручения на публикацию.
Новый тип артефакта: обновить локальную навигацию и этот маршрут при необходимости.
Готовность: результат проверен по критериям задачи, изменения названы точно.
```

Обе локальные инструкции должны реально существовать и вести к своим данным/процедурам. Задача «отредактировать аннотацию» открывает редакционный маршрут, а не каталог учёта. Имена областей — пример, не обязательное дерево.

## 5. Внедрение и развитие

Выбрать канон, области и минимальное чтение. Проверить реальное чтение входа в используемых Claude Code/Codex на тестовой задаче. Отдельный skill для статичного входа не требуется. Skill настройки может создавать/обновлять его, сохраняя местные решения.

При росте измерить порцию и число действий до достаточного контекста; вынести только условно нужное. Изменение маршрута проверять на прежней и новой задаче. Восстановление — предыдущая согласованная редакция вместе с её ссылками; Git применим, если он используется в проекте.
