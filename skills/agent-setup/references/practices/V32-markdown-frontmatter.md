# V32. Frontmatter — структурированные метаданные Markdown

**ID:** V32. **Версия:** 0.1. **Редакция:** 02.11.2026.
**Форма реализации:** соглашение о метаданных, шаблон и потребители полей. **Описание:** на ревью. **Поведенческая проверка:** not-run.

## 1. Когда выбирать

У Markdown-артефактов есть поля, по которым нужно строить реестр, выбирать стрим/стадию, проверять связи или публиковать представления. Frontmatter хранит эти поля рядом с содержанием в одном файле; человек и агент пользуются одними данными.

Нужны понятный потребитель каждого поля и схема для типа артефакта. Если файл просто читают, а метаданные нигде не используются, достаточно обычного текста. Не обязывать все Markdown-файлы иметь одинаковый большой паспорт. Обязательность задаётся типом/областью, а не расширением `.md`.

## 2. Как работает

В начале файла, между двумя строками `---`, располагается YAML-объект с метаданными; ниже остаётся содержательный текст. Инструмент отделяет начальный блок, разбирает его безопасным парсером, проверяет схему и использует поля. Первый YAML-блок внутри примера в середине документа не является frontmatter самого документа.

1. Для каждого поля задать смысл, тип, обязательность, допустимые значения, источник и потребителя. Например, `id` — устойчивая идентичность, `streams` — принадлежность, `stage` — стадия конкретного процесса. Имена — соглашение проекта, не универсальный стандарт.
2. Создавать поля через шаблон нужного типа. Редактировать каноническое значение у его владельца; registry/страницы/фильтры получают производное представление, а не вторую ручную копию.
3. Проверять синтаксис и смысл: корректный YAML ещё не доказывает уникальность ID, существование стрима или допустимость перехода стадии. Повторный ключ не должен незаметно заменять первый.
4. При изменении поля пересобрать или отметить устаревшими зависимые представления. Отсутствующее обязательное поле — диагностика с путём и причиной, а не выдуманное значение.

Даты создания/изменения вводятся только с оговорённым смыслом и источником: mtime файла не доказывает дату документа. Статус во frontmatter не становится вторым независимым жизненным циклом, если оперативное состояние принадлежит Tracker. Метаданные и содержимое могут иметь разные системы-владельцы отдельных фактов — это фиксируется явно.

## 3. Варианты и сочетания

| Вариант | Когда выбирать | Цена / ограничения |
| --- | --- | --- |
| Минимум description | Нужен каталог с содержательными описаниями | Не решает идентичность/связи/стадии |
| Типизированный паспорт артефакта | Нужны выборки по ID/типу/стриму/состоянию | Схема, справочники и миграция требуют сопровождения |
| Специальный формат потребителя, например native SKILL.md | Поля уже определены исполняющей средой | Соблюдать её контракт; не подменять его проектной схемой документа |

Обязательная зависимость — согласованная схема и способ чтения/проверки. Для ручного использования достаточно договорённости; автоматические реестры требуют исполняемого потребителя, которого карточка не поставляет. [V19](V19-folder-registry.md) может использовать поля как источник, [V16](V16-policy-linter.md) — проверять их.

Практика подключается к **V21** (шаблон задаёт паспорт типа), **V04** (метаданные связывают артефакт с одним/несколькими стримами), **V05** (представляют стадию с определённым владельцем), **V09** (ссылка на канон/версию и происхождение копии). Эти механизмы не требуют физически копировать файл в папку каждого стрима. Карточки V21/V04/V05/V09 ещё предстоит заполнить; их связь здесь — контракт применения, не заявление о готовой реализации.

## 4. Минимальный пример

Иллюстрация паспорта вымышленной редакционной заметки. Схема этого примера: все пять полей обязательны, `id` уникален среди активных заметок, `artifact_type` равен `note`, `description` — непустая строка, `streams` — непустой список известных ID потоков, `stage` — одно из `draft/review/published`. В этом варианте стадией владеет сам документ.

```markdown
---
id: NOTE-017
artifact_type: note
description: Порядок проверки источника перед публикацией.
streams: [editorial, research]
stage: review
---

# Проверка источника
Сопоставить утверждение с первичным материалом и сохранить основание.
```

Каталог извлекает ID/description/stage и ссылку на файл; фильтры `editorial` и `research` ведут к одному артефакту NOTE-017. При переходе `review → published` меняется каноническое поле и обновляется каталог. Если фактическим владельцем состояния выбран Tracker, схема должна вместо независимой ручной стадии определить ссылку/производное отображение и протокол обновления.

Этот блок — пример данных, не готовый генератор/валидатор. Он не предписывает одинаковые поля для книги, требования и skill. `streams` задаёт принадлежность, а не разрешение доступа.

## 5. Внедрение и развитие

Начать с потребителей: какие решения/выборки/проверки нужны? Сформировать минимальные схемы по типам, правила множественной принадлежности и владения состоянием. Схему держать в инструкции типа или рядом с шаблоном; не копировать её полностью в каждый документ. Пути к справочникам и условия чтения должны быть доступны из рабочих входов.

Выбрать безопасный YAML-парсер и явную обработку повторных ключей/типов; не исполнять команды из метаданных. Внедрять по оговорённой области: существующие документы с неполными данными сначала диагностировать, неизвестные даты/статусы не заполнять автоматически. Для изменения схемы определить совместимость, миграцию старых файлов и обновление потребителей. Отдельный skill нужен для повторяемой сложной миграции, а не для самого наличия frontmatter.

Откат затрагивает метаданные и потребителей вместе. Перегенерация registry не восстанавливает утраченное значение источника. Изменение стадии с внешними последствиями подчиняется процедуре процесса, а не считается разрешённым одним редактированием YAML.

## 6. Приёмка и границы

**Статус исполнения кейсов:** not-run.

| Кейс | Исходное состояние и действие | Ожидаемый наблюдаемый итог |
| --- | --- | --- |
| V32-T1 | Документ примера; построить каталог и выборки двух стримов | Один ID и один канон; оба фильтра находят тот же файл, описание/стадия извлечены из него |
| V32-T2 | Повторить ключ id либо создать другой файл с NOTE-017 | Диагностика повторного ключа/идентичности; незаметной подмены значения нет |
| V32-T3 | Указать неизвестный стрим или недопустимую стадию | Ошибка схемы с адресом поля; корректность YAML не выдаётся за корректность паспорта |
| V32-T4 | Поменять схему/стадию без обновления каталога | Drift обнаружен либо представление помечено устаревшим; изменённый источник не затирается старой таблицей |

Frontmatter не гарантирует истинность утверждений, действительность одобрения или актуальность внешнего состояния. **P2:** метаданные и текст составляют общий контекст; **P6:** типы/поля и производные поддерживаются согласованно. Объём полей оправдывается потребителями, а не желанием заполнить паспорт.
