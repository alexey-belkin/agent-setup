# V07. Один канон инструкций и доставка в harness

**ID:** V07. **Версия:** 0.1. **Редакция:** 02.11.2026.
**Форма реализации:** конфигурация, symlink или синхронизатор. **Описание:** на ревью. **Поведенческая проверка:** not-run.

## 1. Когда выбирать

В одном проекте используются несколько coding harness; инструкции и skills начинают расходиться. Результат — одно место редактирования и проверяемая доставка в поддерживаемые среды. При одном harness зеркала не нужны. Нужны выбранный канон, перечень получателей и фактическая проверка того, что каждый получатель читает свою точку входа.

## 2. Как работает

Общая инструкция и каждый skill имеют ровно один источник. Дополнительные точки входа указывают на него либо содержат управляемые копии. Зеркало не становится новым skill в каталоге уникальных возможностей. Специфичные настройки/MCP и права harness остаются отдельными настройками, а не побайтной копией чужого формата.

Для копий алгоритм: получить список исходных файлов и их digest → сравнить все получатели до записи → обнаружить конфликт ручной правки → обновить только управляемые копии → сохранить manifest последней доставки → проверить совпадение. Удалять можно только ранее управляемый неизменённый файл, исчезнувший из канона; неизвестные файлы не удаляются. Конфликт останавливает запись до решения, не затирается «синхронизацией».

## 3. Варианты и сочетания

| Вариант | Когда выбирать | Цена / ограничения |
| --- | --- | --- |
| Относительная symlink | Среда/перенос/Git и harness работают с такими ссылками | Проверять цель после клонирования и реальное чтение; направление не универсально |
| Проверяемые копии | Symlink не подходит или нужны обычные файлы | Нужны manifest, check/apply и защита ручных изменений |
| Адаптер с ссылкой/генерацией специального входа | Форматы harness различаются | Нельзя заявлять побайтное равенство разных форматов; проверяется соответствие общих норм |

Обязательная зависимость — читаемый канон и контракт доставки каждого получателя. [V18](V18-root-instruction.md) задаёт смысл корневого входа; [V16](V16-policy-linter.md) может контролировать drift. Смешивать symlink-каталог и алгоритм, который запрещает symlink, без адаптации нельзя.

## 4. Минимальный пример

Иллюстрация двух частей доставки:

```text
AGENTS.md                         # Единственная общая инструкция
CLAUDE.md -> AGENTS.md             # Вариант доставки входа
.agents/skills/review-note/        # Канон skill и его материалов
.claude/skills/review-note/        # Управляемая копия
.cursor/skills/review-note/        # Управляемая копия
```

Имена получателей выбираются под реально используемые среды. Для варианта копий manifest хранит `получатель → относительный файл → digest последней доставки`. После правки канона check сообщает расхождение. Apply обновляет получателя лишь если его старый digest совпадает с manifest; иначе сообщает конфликт с точным путём. Последующий check не находит drift. Это алгоритм, не поставляемая здесь CLI-команда.

## 5. Внедрение и развитие

Зафиксировать канон и поддерживаемые получатели; перенести разошедшиеся ручные правки осмысленно до включения синхронизации. Предпочтительный канон skills — `.agents/skills`, но существующее расположение можно сохранить при явной доставке. Не добавлять `.cursor` только ради симметрии. Отдельный skill синхронизации необязателен; детерминированную работу лучше выполняет скрипт. Готовый переносимый скрипт эта карточка не содержит.

Корневые файлы и полные деревья skills проверяются раздельно. После обновления проверить и ссылки/байты, и вызов skill в каждой заявленной среде. Откатить канон и повторно доставить его, сохранив конфликтующие локальные файлы для разбора. Копирование project MCP вместе с токенами не входит в практику.

## 6. Приёмка и границы

**Статус исполнения кейсов:** not-run.

| Кейс | Исходное состояние и действие | Ожидаемый наблюдаемый итог |
| --- | --- | --- |
| V07-T1 | В каноне изменён материал skill | Check замечает drift; доставка меняет нужные управляемые файлы; повторный check чистый |
| V07-T2 | В одном зеркале вручную изменён тот же файл | Apply сообщает конфликт до записи; ручной текст сохранён |
| V07-T3 | Добавлен неизвестный файл в получателе; исходный skill удалён | Неизвестный файл сохраняется/выдаёт конфликт; удаление старых копий ограничено manifest |
| V07-T4 | После переноса проекта запускаются две среды | Каждая действительно читает вход и находит skill; равенства файлов для этого недостаточно |

Одинаковые инструкции не означают одинаковых возможностей, sandbox или прав. **P2:** единый канон; **P6:** проверяемое обновление; **P7:** чужие локальные данные не затираются молча. Настройка конкретного harness требует проверки его действующих возможностей.
