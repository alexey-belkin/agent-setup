# Agent setup

Переносимый skill для настройки агентского рабочего пространства по постановке человека. Подходит не только для разработки: CRM/пресейл, управление проектами, знания/публикации, хозяйственные процессы. Новое пространство, принятие существующего в развитие и изменение структуры обслуживаются одним навыком.

**Версия: 0.1.2 — обсуждение процесса до сборки.** Агент сначала расспрашивает о целях, желаемой работе и своей роли, возвращает понимание и получает подтверждение; затем подбирает практики и skills под договорённость. [Точный diff и проверки](docs/changes-0.1.2.md). Поведенческая приёмка не заявлена; пробный запуск оставлен пользователю.

## Установка

Склонировать репозиторий и установить **всю папку** `skills/agent-setup`, включая references/assets/scripts. Одного SKILL.md недостаточно. Сначала проверить, что навыка с таким именем ещё нет; существующую установку обновлять с сохранением локальных изменений.

```bash
git clone https://github.com/alexey-belkin/agent-setup.git
```

Для Codex скопировать `skills/agent-setup` в `~/.agents/skills/agent-setup` (все проекты) либо `<project>/.agents/skills/agent-setup` (один проект). Для локального Claude Code — в `~/.claude/skills/agent-setup` либо `<project>/.claude/skills/agent-setup`. В подходящей локальной среде допустима symlink на канон вместо копии. Обнаружение в облачных/управляемых режимах может отличаться: [Codex skills](https://learn.chatgpt.com/docs/build-skills), [Claude Code skills](https://code.claude.com/docs/en/skills).

## Использование

Открыть целевой проект в новой сессии выбранного harness. Пример для Codex:

```text
Используй $agent-setup. Настрой в текущей папке пространство для ...
Работаем в Codex. Исходные материалы: ...
Нужно уметь: ...
Критерии результата: ...
Пробный запуск выполню сам; подготовь инструкции и тестовые задачи.
```

В Claude Code вызвать `/agent-setup` и дать ту же постановку. Существенны бизнес-задача, корень/данные и ограничения; не нужно заранее проектировать агенту дерево папок. Для существующего проекта написать «прими существующее пространство в развитие», для изменения — назвать новый поток/процесс. Если поручено только проектирование, указать это.

Перед настройкой агент задаст короткую серию вопросов о вашей работе и предложит согласовать понимание процесса. Не нужно заранее выбирать практики и навыки: их подбор следует из договорённости. Уже подтверждённый процесс повторно обсуждать не требуется.

## Что создаёт навык

- Общий вход и достаточные прямые маршруты, локальные правила под задачи, каноны и связи с внешними ресурсами.
- Конкретные рабочие процедуры и минимальные типы артефактов, где хранить результат и как его проверить.
- Обязательный установленный auto-improve с триггером и прямым маршрутом из рабочего входа; порядок развития, версии/локальные отклонения, gaps и продолжение.
- Приёмочные задания и честный статус выполненных проверок.

Основная среда MVP — Claude Code/Codex, человек в цикле LLM-3. Перспектива LLM-4 оценивается по конкретному потоку и его контролю. Навык не выдаёт отсутствующие права, не подключает все интеграции автоматически и не публикует результаты без поручения.

Этот репозиторий — канон выпускаемого skill. Все необходимые runtime-материалы находятся внутри `skills/agent-setup`; исходные личные проекты автора не нужны и не входят в публикацию. Подробная библиотека ещё развивается; краткие решения не объявляются готовыми генераторами/сервисами.

Для обратной связи: задача/ожидание, версия/harness, фактический результат, где агент отклонился, обезличенные примеры и желаемая правка. Не прикладывать секреты и клиентские данные. Исправления процесса вносить в канон с обновлением зависимых маршрутов.
