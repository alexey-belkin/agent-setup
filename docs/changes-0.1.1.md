# Обновление 0.1.1 — 02.11.2026

Исправления по обратной связи первого применения v0.1.0. Пользователь поручил изменить пакет и опубликовать обновление. Целевой пользовательский проект не редактировался этим выпуском; его реальная операционная задача ещё выполняется и не считается успешной поведенческой приёмкой.

## 1. Auto-improve — обязательный исполняемый компонент ядра

В v0.1.0 процедура могла остаться текстом раздела сопровождения. Теперь [CORE, §5](../skills/agent-setup/references/practices/CORE.md#5-обязательный-навык-auto-improve-v15) требует проектный `auto-improve/SKILL.md`, поддерживаемую доставку, локальный триггер и ссылку из рабочего входа.

- [SKILL.md, Маршрут, абзац после шага 5](../skills/agent-setup/SKILL.md): добавлены установка готового навыка, проверка поставки и различение установленного skill/текстовой записи. Шаг 3 исключает V15 из опционального выбора.
- [Готовый исходник](../skills/agent-setup/assets/templates/auto-improve.template.md) — полноценный native skill с `name: auto-improve`, description и шестью шагами; без незаполненных полей. При развёртывании копируется/адаптируется как проектный SKILL.md. Не перезаписывать полезную существующую реализацию.
- [Deployment, §5](../skills/agent-setup/references/deployment.md#5-что-оставить-для-развития) задаёт пути Codex/Claude, канон/доставку, ссылку/триггер и проверку. [Project AGENTS, Управление и развитие](../skills/agent-setup/assets/templates/project-agents.template.md) и [checks, Обязательная проверка](../skills/agent-setup/assets/templates/checks.template.md) передают эти требования целевому пространству.
- [V15, §1/5](../skills/agent-setup/references/practices/V15-auto-improve.md) и [меню](../skills/agent-setup/references/practices/README.md) согласованы с ядром. Наличие карточки/строки выбора не равно установке.

Дословный фрагмент V15 §5 **было → стало**: «Встроить короткий триггер в локальный процесс, подробную процедуру — в один skill/command.» → «Встроить короткий триггер и ссылку в рабочий вход, установить подробную процедуру как проектный auto-improve/SKILL.md в обнаруживаемом каталоге harness; обычного раздела карты или legacy-command для поставки agent-setup недостаточно.»

[check_auto_improve.py](../skills/agent-setup/scripts/check_auto_improve.py) проверяет присутствие, базовые поля и локальную достижимость по inline Markdown. Это **не** полный YAML-валидатор, подтверждение обнаружения конкретной средой или запуск навыка. Штатная проверка manifest и фактическая видимость/поведение фиксируются отдельно. Helper не изменяет проверяемые файлы.

## 2. ID вместе с кратким названием

[Spec-authoring, §4.1/4.2](../skills/agent-setup/references/spec-authoring.md#4-сборка-модели-в-обоих-режимах), [deployment, §1](../skills/agent-setup/references/deployment.md#1-от-задачи-к-рабочему-устройству), шаг 3 [SKILL](../skills/agent-setup/SKILL.md) и [STANDARD, §5](../skills/agent-setup/references/practices/STANDARD.md#5-как-агент-проектирования-использует-меню) распространяют правило на каждую отсылку, обе стороны ребра, таблицы решений и текст. Определения ID в соседней таблице недостаточно.

В spec-authoring §4.2 фрагмент **было → стало**: «Для существенного ребра указать ID обеих сторон,» → «Для существенного ребра указать ID и краткое название каждой из обеих сторон,». Добавленный дословный пример в §4.1: `PRJ-A01 (исходники) → PRJ-E01 (публикация)`. В [workspace-spec, §2/3/5](../skills/agent-setup/assets/templates/workspace-spec.template.md) уточнены подписи и заголовки таблиц; в project-agents добавлен пункт рабочего контракта. Идентификаторы не переименовываются и не теряют устойчивость.

## 3. Настроечные артефакты в setup/

В новом пространстве отдельная карта по умолчанию — `setup/WORKSPACE.md`, каталог проверок — `setup/CHECKS.md`, свидетельство описи — `setup/inventory-before-YYYY-MM-DD.json`. Они создаются только при нужной функции. AGENTS остаётся рабочим входом, предметные и auto-improve skills — в каталогах harness, предметные результаты — у объектов/потоков.

Изменены [deployment, §3](../skills/agent-setup/references/deployment.md#3-минимальная-структура-по-функциям), [spec-authoring, §4.3](../skills/agent-setup/references/spec-authoring.md#43-git-исключения-и-доставка), начала [workspace-spec](../skills/agent-setup/assets/templates/workspace-spec.template.md) и [checks](../skills/agent-setup/assets/templates/checks.template.md), каталог шаблонов и шаблон сопровождения. Дополнительные нормы не превращают чтение всей настройки в обязательный шаг каждой операции.

Для существующих проектов сохранить работающие каноны либо мигрировать в пределах поручения: составить old/new пути, пересчитать **входящие и исходящие** ссылки/якоря/assets, обновить checker/config/launchers и проверить прежние маршруты. При необходимости оставить согласованный redirect/совместимый launcher, а не независимую редактируемую копию. Массовое перемещение только ради имени папки не требуется.

Формат основного skill и копии native asset проверяется skill-creator quick_validate; общий статический протокол — [package-check.json](package-check.json).

Результат — [auto-improve-static.json](auto-improve-static.json). Это тесты read-only helper, без вызова модели/настройщика/auto-improve на реальном проекте.

В [acceptance](../skills/agent-setup/references/acceptance.md) добавлены A09–A11 с ожиданиями для новой сессии; **строки A00–A08 не менялись**. Новые и прежние поведенческие кейсы не исполнены этим выпуском. Исправление контракта, поставка и подготовка проверки не выдаются за успешное поведение. Текущая пользовательская задача не объявлена pass.
